# Show HN Launch: rules

## What good looks like
A developer reads the README, runs the quickstart in under a minute, and sees it work. On launch day the maker is present all day, answers every question in their own words, and ships quick fixes the same week. Rank is a side effect; trying it is the goal.

## Rhythm (4 weeks)
1. Week 1: verify the quickstart from scratch and rewrite the README around it.
2. Week 2: demo recording, release notes, the fact sheet and the launch post.
3. Week 3: readiness check, launch, and a launch-day run sheet with who answers and who fixes.
4. Week 4: fixes from feedback, a recap, and good-first-issues for new contributors.

## Craft
- The first screen of the README says what it does, shows the one command to try it, and shows the output.
- The quickstart runs in a clean environment, tested by the demo-builder, not assumed.
- Known limits go in the README and the fact sheet. Developers trust honest limits.
- Release notes list breaking changes first.

## Readiness checklist
- Quickstart passes in a fresh container on the documented platforms.
- Install path and docs links work.
- Issues are triaged and the maker is free on launch day.

## Definition of done
- Each asset is approved and shipped, with its URL recorded.
- The maker wrote and posted the Show HN, and the thread URL is recorded.
- The recap lists visits, stars, installs, top feedback and the fixes queued.

## Non-negotiables
- OMA never writes text that gets posted to Hacker News.
- No vote requests anywhere, and one Show HN per launch.
- Launch copy describes what's true today.
- Channel rules: `channels/hacker_news.md`, `channels/github.md`, `channels/site.md`.

## Measuring
- Leading: checklist on time, launch-day visits and stars, comment response time.
- Lagging: the launch cohort's first successful use within 14 days, and new contributors.

## Failure modes
- Launching before the quickstart works for strangers.
- The maker disappearing after the first hour.
- Treating rank as the goal.
